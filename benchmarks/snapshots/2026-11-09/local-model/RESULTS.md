# Локальна модель: вимір часу 09.11.2026

Qwen3-Coder 30B / Q4_K_M (`qwen3-coder:30b`, digest `06c1097efce0…`), Ollama 0.40.15, Apple M5 Pro, 48 GiB RAM. Модель обрана з локальної конфігурації Continue та встановленого списку Ollama. Context 16 384; temperature 0; seed 42; максимум output 384. Це одиничні extraction-запити до локальної моделі, не повний агентський coding workflow.

Завантаження/ініціалізація моделі, що не була resident: **14,72 с**, окремо від A/B. Файловий кеш ОС не контролюється. Resident allocation за Ollama: **18,7 GiB**, 100% GPU за `size_vram == size`. Це не вимір peak RAM усієї системи.

## 48 основних запитів

Медіани трьох парних повторів. Повний час = читання baseline або CLI-фільтр + HTTP inference до завершення відповіді. Навантаження ОС і thermals не ізольовані; це приклади, а не гарантія прискорення.

`fresh`: weights уже в RAM, ранній marker змінено; переважна частина input не кешована. Це не cold SSD/model load. `repeat`: повторюємо CLI та задачу; реальний cache hit перевіряємо за API. Для status, navigation і jq repeat-пари мають однакові SHA-256; у RTK tsc порядок груп змінився. У первинному описі runner слово «ідентичний» було неточним: методику уточнено після аудиту, числові виміри та відповіді не змінені. Історичні source-файли runner збережені з SHA-256 із metadata.

Input — повний input runtime Qwen з інструкцією/template, **не o200k_base** початкових CLI-графіків. Cached — частина input; його не треба додавати ще раз. Output у головному jq-кейсі становить 224 токени в обох варіантах. Усі 48 latency включені в медіани, навіть коли відповідь помилкова; правильність показана поруч. 45/48 відповідей правильні: baseline 21/24, filter 24/24. Цього недостатньо для загальної заяви про якість моделі.

## Контроль однакового payload: ще 12 запитів

Тільки TypeScript case, `--freeze-repeat`: повторення використовує точний попередній текст, без повторного CLI. Для повторів cached count raw 159/160, filtered 214/215. Медіана request wall: **0,317 / 0,323 с**. Усі 12 відповідей правильні. Перші запити контролю не інтерпретуються як cold: модель уже resident і частина префіксів була в кеші.

У звичайному CLI-repeat RTK tsc отримав лише 106–121 cached tokens із 215 через зміну порядку, а raw — 159 із 160. Повний час repeat зріс із **0,351 до 0,460 с**. Контроль показує, чому важливі сталість input та накладні витрати, а не сам лічильник токенів.
